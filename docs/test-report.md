## Not run / remaining quality gates

- Browser walkthrough on 2026-10-28 (Chromium, 1440×900): admin enabled the snapshot policy through the Settings form (values persisted after a fix), employee clock-in triggered the screen-share request which the automated browser declined — the UI showed the honest permission warning and the server recorded `capture_unavailable`, and the manager Team attendance "View frames" browser opened showing that record. No page JS errors; only the expected pre-login `auth/me` 401.
- Two bugs found and fixed during that walkthrough: the 60-second background refresh re-rendered the active view and wiped in-progress form input (now suppressed while an input has focus or a modal is open), and the selected view persisted across sign-out/sign-in so an employee could land on the admin-only settings error (view and nav now reset on login).
- Granted-permission capture path verified in the browser on 2026-10-28 by substituting a same-shape `MediaStream` (animated 960×540 canvas) for the screen picker this automated browser cannot grant; everything downstream (video element, canvas frame grab, base64 upload, server scheduling) ran unmodified: 7 frames were captured over about 7 minutes, each uploaded within ~1 second of its server-issued due time with randomized intervals of 41–51 seconds inside the configured 30–60 second range; stored bytes round-tripped through the image endpoint with valid JPEG magic (`FF D8`, 13.6 KB); no new rows appeared in the 70 seconds after clock-out (loop stops); the manager frame browser rendered all 7 real thumbnails at 960×540 plus the one `capture_unavailable` tile. This run found and fixed a third bug: the just-granted stream was torn down by `syncCapture` running against pre-clock-in client state, and the indicator did not re-render on grant — stream shutdown now happens only after clock-out is confirmed.
- Still not exercised in a browser: the actual OS screen-share picker accept flow (only the identical post-grant code path was exercised), keyboard/screen-reader/mobile-viewport review, and any general full-workflow E2E beyond this snapshot path.

- HTTP tests cover core journeys but not correction rejection/clarification, timesheet rejection/reopen, same-key conflicting payload through HTTP, parallel concurrent punches, cross-tenant authenticated HTTP reads, CSV malicious formula fixture, session expiry or rate limiting.
- No schedules, holidays, leave, invitations, employee administration UI, project/activity administration, recovery email, configurable overtime/pay-period policies, office legal/payroll rule review, backup/restore drill or production smoke test.
